# Phase 4 — game module, hexagonal (core/domain, core/port, core/service + adapters) + ACL

Workers read first: `docs/designs/go-modular-monolith-example.md` §1 (orders module) + §5. Style: hexagonal — `internal/game/internal/core/{domain,port,service}` + `internal/game/internal/adapter/inbound/http` + `internal/game/internal/adapter/outbound/{postgres/, scheduleacl.go}`.

Prerequisite: phase 3 done (schedule facade + game-facing surface exist).

## Mappings
- `rides.go` (751 lines) splits three ways:
  - `core/domain/ride.go`: Ride, RideState + consts, ErrInvalidTransition, transitions/canTransition, the state-machine methods (Create, WonPending, Lost, Lock, Burn, Unlock), streakRate, bonusDelta, calculateBonus, ValidateRide, ValidateRideState. **KEY CHANGE:** the transitions map and methods currently key on `schedule.RoundPhase` (rides.go:615–720) — the domain now uses a game-owned `Phase` type with the same semantics. No schedule import in domain.
  - `core/port/ride_repository.go`: consumer-side interface with exactly what the service needs (Get, GetAll, Insert, InsertTx, LockedForMatchTx, UndecidedForMatchesTx, ArriveTx, Update, DecisionGuardedTx, ExistsForMatch, ExistsForTeam).
  - `adapter/outbound/postgres/ride_repo.go`: `RideRepository` implementing it; SQL unchanged (rides.go:78–613); classifyArrivalRefusal/classifyDecisionRefusal stay here; errors map → game domain sentinels.
- `players.go` (248) → `core/domain/player.go` (Player, ValidatePlayer) + `core/port/player_repository.go` + `adapter/outbound/postgres/player_repo.go` (PlayerRepository incl. ExistsForTeam, DeleteForSeason — these become game facade capabilities consumed by schedule's `GameUsage` port from phase 3).
- `schedule_port.go` (59) → `core/port/schedule.go` **REDEFINED with game-owned types**: PhaseForMatch(ctx, matchID) (Phase, error); NextForTeam(…) (game-owned NextMatch struct, error); RoundOpenTx/DestinationOpenTx (tx params as today — pragmatic: the port may name the pgx tx type); Match(ctx, id) (game-owned MatchSnapshot, error); Team(…). **ERROR CONTRACT FLIP (this phase):** the port returns game-owned sentinels (ErrNoNextMatch, ErrRoundNotOpen, ErrInvalidRoundPhase, ErrNotFound, …) instead of `persistence.ErrRecordNotFound`; ALL game call sites checking `store.ErrRecordNotFound` (service.go:66–67, 83, 249 + events.go) switch to game sentinels in the same commit.
- `adapter/outbound/scheduleacl.go` (NEW): wraps the schedule facade's game-facing surface; implements `core/port/schedule.go`; translates schedule types → game-owned types (incl. schedule.RoundPhase → game Phase, schedule.Match → MatchSnapshot) and schedule errors (incl. schedule.ErrNotFound) → game sentinels. This is the ONLY game package allowed to import schedule.
- `service.go` (426) → `core/service/ride_commands.go`: ErrRoundNotOpen/ErrNoNextMatch/ErrInvalidRoundPhase (domain/port errors), Service{ports only: rideRepo, playerRepo, schedule port, ledger port, idempotency port, bus, log, clock}, RideCreate/RideLock/RideBurn/RideUnlock (claim-first, one tx, stored response — unchanged), RidePhase (**clock injected** — no inline time.Now(), service.go:107–120). `s.Store.Pool.Begin` (service.go:138, 220, 300, 366) → a consumer-side `Transactor` port (Begin(ctx) (Tx, error)) implemented in adapter/outbound/postgres. rideResponse marshaling moves to the transport DTO.
- `events.go` (318) → `core/service/settlement.go`: OnMatchResultRecorded, OnRoundCompleted, settleRideFromResult, resultAgreement, teamOdds, runEvent, matchResultEndpoint, roundCompleteEndpoint, settlementLockClass/settlementLockSQL (advisory-lock SQL is a persistence detail — may live in the postgres adapter; behavior identical), idempotency claim + marshal/hash logic unchanged. Consumes ports only.
- **Async ACL:** the eventbus subscriptions (cmd) currently hand schedule's `MatchResultRecorded`/`RoundCompleted` payloads straight into the service. Wrap them: the subscription adapter (cmd or the ACL) translates schedule's event payload into a game-owned command/event type before it enters game's service. Schedule's event types remain schedule's public contract; game's core never imports them.
- `store.go` → **DIES**. Facade `internal/game/game.go`: `Module`, `NewModule(pool, scheduleAPI (schedule facade), ledgerAPI, idempotency, bus, log)`, DTOs (incl. RideDTO + the usage capabilities schedule needs: PlayersExistForTeam, RidesExistForTeam, RidesExistForMatch, DeletePlayersForSeason), `RegisterRoutes`.
- `core/port/ledger.go`: game-owned LedgerPort (current `ledger.Ledger` interface shape, consumer-side); satisfied structurally by the ledger package (its light rename is phase 5; game must not import ledger's concrete Store).
- `core/port/idempotency.go`: game-owned port over what game uses (token validation, Claim/Save on the caller's tx); satisfied by the idempotency package.
- Transport `adapter/inbound/http/`: `rides.go`, `players.go` (from api/rides.go, api/players.go — incl. rideCommand token handling, Location header derivation api/rides.go:239–251, gameErrorResponse mappers from api/errors.go); `dto.go` (rideMarshal/rideCreateMarshal/rideResponse → DTOs, json tags verbatim; the hardcoded ledger stub api/rides.go:201–208 is preserved with its TODO); `routes.go` — game's route table, identical paths/methods/middleware. `userCanManagePlayer` (api/players.go:20–27) moves from transport INTO the service use case (authorization is business policy) — the handler passes the authenticated user; HTTP status mapping preserved.
